# Тестування протоколу ARP

## Тестове середовище

| Вузол             | ОС         | Інтерфейс | IPv4               | MAC                 |
| ----------------- | ---------- | --------- | ------------------ | ------------------- |
| Ноутбук           | Arch Linux | `wlan0`   | `192.168.50.32/24` | `14:ac:60:6e:b9:f1` |
| Віртуальна машина | Arch Linux | `enp0s3`  | `192.168.50.37/24` | `08:00:27:d9:55:23` |
| Роутер            | —          | —         | `192.168.50.1`     | `bc:fc:e7:ac:8f:f0` |

Ноутбук і ПК підключені до локальної мережі через Wi-Fi. Адаптер VM у VirtualBox працює в режимі мережного моста до Wi-Fi-адаптера ПК. Захоплення виконується на ноутбуці, інтерфейс `wlan0`, фільтр відображення `arp or icmp`.

Усі команди нижче виконуються **на ноутбуці**.

## Отримання MAC за IP

**Передумови:** VM увімкнена; вузли перебувають в одній підмережі; у Wireshark розпочато захоплення.

**Кроки:**

1. Видалити запис VM та перевірити його відсутність:

   ```bash
   sudo ip neigh del 192.168.50.37 dev wlan0
   ip neigh show to 192.168.50.37 dev wlan0
   ```

   Якщо запису вже немає, команда видалення може повідомити `No such file or directory`; порожній вивід другої команди підтверджує передумову.

2. Запустити обмін:

   ```bash
   ping -4 -c 4 192.168.50.37
   ```

3. Знайти ARP Request і ARP Reply у Wireshark.

**Очікуваний результат:** ноутбук надсилає `Who has 192.168.50.37? Tell 192.168.50.32`, VM відповідає `192.168.50.37 is at 08:00:27:d9:55:23`; після цього відбувається ICMP-обмін.

## Оновлення ARP-таблиці

**Передумови:** збережено стан таблиці до обміну з TC-ARP-01; отримано ARP Reply. Тести 01 і 02 можна виконати в одному захопленні.

**Кроки:** після ping виконати:

```bash
ip neigh show to 192.168.50.37 dev wlan0
```

Порівняти запис із таблицею до ping та MAC у відповіді ARP.

**Очікуваний результат:** після обміну з’являється динамічний запис `192.168.50.37 → 08:00:27:d9:55:23`.

## Використання статичного запису

**Передумови:** відома правильна MAC-адреса VM; зв’язність вузлів перевірена.

**Кроки:**

1. Створити статичний запис і перевірити його:

   ```bash
   sudo ip neigh replace 192.168.50.37 lladdr 08:00:27:d9:55:23 nud permanent dev wlan0
   ip neigh show to 192.168.50.37 dev wlan0
   ```

2. Переконатися, що стан — `PERMANENT`, і почати **нове** захоплення у Wireshark.
3. Виконати:

   ```bash
   ping -4 -c 4 192.168.50.37
   ```

4. Перевірити ICMP-відповіді. Для пошуку запитів саме ноутбука щодо MAC VM застосувати фільтр:

   ```text
   arp.opcode == 1 && arp.src.proto_ipv4 == 192.168.50.32 && arp.dst.proto_ipv4 == 192.168.50.37
   ```

**Очікуваний результат:** запис має стан `PERMANENT`, ping успішний, за наведеним фільтром у новому захопленні немає пакетів.
